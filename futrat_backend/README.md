# Backend на Python 3.15.0

[Развёртывание на Ubuntu с существующими Docker Caddy и PostgreSQL](deploy/README.md).

Текущий [список 31 турнира и настройка ESPN + GOAL](docs/data-sources.md).

[Прогнозы, избранное, профили игроков и составы: правила, API и ограничения данных](docs/interactive-features.md).

Backend закреплён на CPython 3.15.0 с обычным GIL. Исходные прямые зависимости находятся в `requirements.in`, тестовые — в `requirements-dev.in`. Файлы `requirements.txt` и `requirements-dev.txt` содержат согласованные версии всех транзитивных зависимостей и хеши дистрибутивов. Устанавливайте их целиком: отдельное обновление пакета может нарушить совместимость.

## Установка

Работайте из каталога `futrat_backend`. Установите [uv](https://docs.astral.sh/uv/getting-started/installation/) и создайте окружение:

```powershell
uv python install 3.15.0
uv venv --python 3.15.0 .venv
uv pip sync --python .venv/Scripts/python.exe --require-hashes --only-binary=:all: requirements-dev.txt
uv pip check --python .venv/Scripts/python.exe
```

На Linux/macOS замените путь к интерпретатору на `.venv/bin/python`. Для запуска backend нужны переменные `DATABASE_URL`, `SECRET_KEY`, `ALGORITHM` и `ACCESS_TOKEN_EXPIRE_MINUTES`. Существующий `postgresql://...` поддерживается и использует `psycopg2`; новый адрес можно указать как `postgresql+psycopg2://...`. Не храните рабочие секреты в репозитории. Для контейнерного запуска существующий `docker-compose.yml` собирает runtime-образ и использует PostgreSQL 15; его настройки предназначены для локальной разработки.

При изменении прямых зависимостей пересоздайте оба lock-файла одной версией uv и проверьте результат на Windows и Linux:

```powershell
uv pip compile requirements.in --universal --python-version 3.15.0 --generate-hashes --prerelease disallow -o requirements.txt
uv pip compile requirements-dev.in -c requirements.txt --universal --python-version 3.15.0 --generate-hashes --prerelease disallow -o requirements-dev.txt
```

## Проверка

Обычный `python -m pytest -q` использует изолированную SQLite. Для проверки PostgreSQL 15 запустите тестовый Compose-проект: его БД размещена в `tmpfs`, а опубликованный порт выбирается системой. Пустой `tests/compose.env` не даёт Compose автоматически подхватить локальный `.env`.

```powershell
docker compose --env-file tests/compose.env -p futrat-python-upgrade -f compose.test.yml up -d --wait db
docker compose --env-file tests/compose.env -p futrat-python-upgrade -f compose.test.yml run --build --rm --no-deps tests
docker compose --env-file tests/compose.env -p futrat-python-upgrade -f compose.test.yml down --remove-orphans
```

Тесты блокируют внешние HTTP-запросы и принимают только тестовую БД `futrat_upgrade_test` на локальном хосте или сервисе `db`. Они проверяют авторизацию, старые bcrypt-хеши и JWT, API и OpenAPI, запись в PostgreSQL, синхронизацию матчей, запуск планировщика и реальный HTTP-запуск Uvicorn.

На 16 октября 2026 года полный набор из 28 тестов прошёл на Python 3.15.0 в Windows и Linux-контейнере с отдельной PostgreSQL 15. `pip check` также прошёл на обеих платформах. Все 20 маршрутов OpenAPI сохранились; у ответа об ошибке валидации FastAPI появились только необязательные поля `input` и `ctx`. Проверен разбор ответов регистрации, входа, профиля, турниров и матчей существующими Dart-моделями Flutter.

## Совместимость и откат

Пароли остаются в формате bcrypt с 12 раундами. Новый код сохраняет поведение старого Passlib для паролей длиннее 72 байт UTF-8, поэтому существующие хеши проверяются без сброса паролей. Формат JWT и схема БД не менялись. Перед развёртыванием в иной среде повторите тесты с её Python, архитектурой и способом установки зависимостей.

Если потребуется откат, верните прежний образ или прежний набор зависимостей backend. Миграция БД не требуется, поскольку её схема этим обновлением не менялась. Отдельно проверьте вход для учётных записей, созданных после обновления, прежде чем переключать рабочий трафик обратно.

## Загрузка текущих сезонов

При старте API создаётся дополнительная таблица `tournament_sync_states`: календарь ESPN, границы сезона и успешно обработанные даты. Существующие таблицы матчей и пользователей не изменяются. Загрузка сезона запускается в фоне, поэтому API доступен до её завершения. Каждая игровая дата запрашивается отдельно: диапазоны дат в soccer scoreboard возвращают HTTP 400. Для календарей со стадиями кубка или без списка дней сначала запрашиваются календарные годы, затем выбираются игровые даты внутри границ сезона. Если годовой ответ достигает лимита событий, проверяются отдельные дни сезона. Перехода на запрос без дат больше нет.

Полная задача запускается при старте и затем раз в 6 часов. Она продолжает пропущенные даты; при обновлении календаря перепроверяет объявленные будущие матчи. Завершённая история сохраняет контрольные точки. Отдельная задача каждую минуту обновляет игровые даты в пределах двух дней от текущей. Запросов одновременно не больше четырёх; временные сетевые ошибки, HTTP 429 и 5xx повторяются до трёх попыток. Ошибка одной даты или лиги не останавливает остальные. Сохранение матчей и контрольной точки выполняется одной транзакцией. PostgreSQL advisory lock защищает базу от одновременной синхронизации разными процессами.

Матч определяется ID события внутри турнира. Перенос даты и изменение счёта обновляют существующую запись, сохраняя связи с оценками и прогнозами. Списки матчей и расчёт таблицы используют границы сезона из ESPN; старые записи остаются доступны по ID. Когда источник не передаёт официальный номер тура, приложение использует порядковый номер игры команды по календарю всего сезона; у перенесённых встреч он может отличаться от официального тура.

Запуск и просмотр прогресса:

```powershell
docker compose up -d --build
docker compose logs --tail 40 web
$table = Invoke-RestMethod http://localhost:8000/api/tournaments/1/standings
$table | Select-Object @{Name='team';Expression={$_.team.name}},played,points
```

ID турнира можно получить из `/api/tournaments`. После завершения первоначальной загрузки переключите лигу в мобильном приложении либо откройте его заново, чтобы обновилась сохранённая на экране таблица. Compose использует DNS Docker по умолчанию: ручная правка `/etc/hosts` или `/etc/resolv.conf` не требуется.

Для принудительной повторной проверки всех дат используйте `docker compose exec web python -c "from app.initial_data import update_all_data; update_all_data(force=True)"`. Если синхронизация уже выполняется, команда пропустит запуск и запишет это в лог. Объём загрузки ограничен опубликованным календарём источника; отсутствующие в ESPN турниры и ещё не опубликованные встречи не подменяются вымышленными данными. Например, кода `rus.cup` нет в каталоге ESPN, а Суперкубок Испании использует код `esp.super_cup`.
